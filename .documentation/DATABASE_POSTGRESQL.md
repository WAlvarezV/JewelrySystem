## 2. Configuración en la Solución .NET 10

### 2.1 Proveedor Centralizado (`Directory.Packages.props`)
Se utiliza el paquete centralizado:
```xml
<PackageVersion Include="Npgsql.EntityFrameworkCore.PostgreSQL" Version="10.0.3" />
```

### 2.2 Inyección en Proyectos de Infraestructura
Todos los proyectos `*.Infrastructure.csproj` referencian:
```xml
<PackageReference Include="Npgsql.EntityFrameworkCore.PostgreSQL" />
```

Y registran su contexto mediante:
```csharp
services.AddDbContext<MyDbContext>(options =>
    options.UseNpgsql(connectionString));
```

### 2.3 Manejo de Fechas y Timestamps
Para evitar problemas con tipos de fecha `Unspecified` provenientes de migraciones o formularios sin zona horaria, se configuró el switch global en [Program.cs](file:///E:/repos/JewelrySystem/src/Host/JewerlySystem.Web/Program.cs):
```csharp
AppContext.SetSwitch("Npgsql.EnableLegacyTimestampBehavior", true);
```
Adicionalmente, el `AuditInterceptor` escribe las marcas temporales (`CreatedAt`, `LastModifiedAt`) en UTC mediante `DateTime.UtcNow`.

## 4. Secuencias de Autoincremento (`SERIAL / IDENTITY`)

Las tablas con columnas `Id` autoincrementales utilizan secuencias administradas por PostgreSQL bajo el estándar `GENERATED BY DEFAULT AS IDENTITY`:

* `public."IdentificationTypes_Id_seq"`
* `public."Brands_Id_seq"`
* `public."ItemTypes_Id_seq"`
* `public."Persons_Id_seq"`
* `public."Items_Id_seq"`
* `public."Jewelry_Id_seq"`
* `public."Watches_Id_seq"`
* `public."DailyRecords_Id_seq"`
* `public."Contracts_Id_seq"`
* `public."Payments_Id_seq"`
* `public."Invoices_Id_seq"`

> [!TIP]
> Si se insertan registros con IDs explícitos (como en migraciones de datos), la secuencia debe sincronizarse al valor máximo actual ejecutando:
> ```sql
> SELECT setval(pg_get_serial_sequence('"{Tabla}"', 'Id'), COALESCE((SELECT MAX("Id") FROM "{Tabla}"), 1));
> ```
